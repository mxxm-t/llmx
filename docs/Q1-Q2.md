# Q1_0 and Q2_0 weight support

This is the implementation and qualification plan for read-only inference.
Metadata recognition already exists. Neither format is qualified for inference
at this checkpoint. The branch starts from `c601fc31e` after NVFP4 landed.

## Format contract

| Format | GGUF type | Values per block | Bytes | Packed code |
|---|---:|---:|---:|---|
| Q1_0 | 41 | 128 | 18 | One bit per value, 0 gives -1 and 1 gives +1 |
| Q2_0 | 42 | 64 | 18 | Two bits per value, codes 0/1/2/3 give -1/0/+1/+2 |

Both begin with a little-endian binary16 scale, followed by 16 packed bytes.
Values use consecutive fields from the least-significant bit upward in each
byte. Multiply the signed code by the decoded scale. Retain negative scales,
subnormal scales and signed-zero behavior. Q2_0 code 3 is part of the storage
contract even when a ternary model does not emit it.

The Q1_0 reference inspected locally is mx-llama.cpp commit
`407d0bb1f12eaa49882d2714a93fe774eb6806f2`, `ggml-common.h` and
`ggml-quants.c`. The official Q2_0 contract is documented in
[upstream PR 24448](https://github.com/ggml-org/llama.cpp/pull/24448), merged
as `ed93eda0d87269d944b64d3efdb49210d6a9fb9e`. Its group size is 64.
The earlier fork-only group-128 Q2_0 and PQ2_0 are distinct layouts and must
not be used as type-42 fixtures. Reference source is inspected for the format
and behavior, not copied into llmx.

## Owners and work order

1. `quant/types.hpp` keeps the existing storage geometry and adds the named
   execution constants. A small `quant/low_bits.hpp` owns the two block
   decoders. `quant/quant.hpp` registers them. No CLI or model-specific decoding.
2. Independent raw fixtures cover every field position, all codes, blocks,
   finite scale extremes, negative scales, signed zero and output guards.
   The format reference must not call the runtime decoder.
3. Vulkan's existing quant descriptors, block decoding and matrix families
   own GPU execution. Keep per-format unpacking in one shader helper and
   reach it through embeddings, row products, prompt tiles and routed products.
   Reuse existing dtype policy and range repair. Do not add tuning flags.
4. Validate standalone and grouped/residual/routed operations, dimension tails,
   dispatch thresholds, row classes and explicit F32/F16/BF16 policies. Add
   tiny independent HF fixtures and exercise layer/tensor split loading.
5. Pin a complete supported-architecture file for each format, inventory every
   tensor type, and compare against file-exact HF at short and raw/chat 16K
   contexts. Measure a matched mx Vulkan comparison before advancing beyond
   the quant stage. Record absent reference paths rather than inventing parity.
6. Run applicable final identity, CPU/device/Windows and hosted checks once
   the implementation is complete. Keep failures and all planned timing samples.

Q1_0 and Q2_0 can share scale loading, the registry and product infrastructure,
but not their bit unpacking or value map. Their two real implementations
justify one small family owner, not a generic arbitrary-bit-width framework.

Early development runs only the affected format/operator checks. Performance
screens precede expensive model qualification for kernel alternatives.
No numerical budget is changed to clear an unexplained failure. A mismatch
gets a controlled reference/precision investigation before any gate decision.

For focused fixed-budget two-device tensor checks, `--tensor-width 2
--layer-shares 1` names the single stage explicitly. This preserves its
placement while avoiding the automatic fit's five-second memory-settling
wait on every process start. A failed initial fit can still wait for memory.
Record these flags with each check; they do not qualify automatic placement.
Existing fixed plans retain their original commands and results.
