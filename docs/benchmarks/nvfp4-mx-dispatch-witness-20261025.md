# MX Radeon dispatch witness (2026-10-25)

This page records the 2026-10-25 Radeon debug witness and the comparison made at that checkpoint. Later evidence is linked explicitly below. Descriptions of llmx input staging in the experiment discussion are historical.

The pinned c4d12e2c debug build actually selected 212 `matmul_nvfp4_f32_aligned_1` tile and 220 `mul_mat_vec_nvfp4_f32_f32` row dispatches on Radeon VII. The selected tile is the medium 64x64/BK32 scalar path with 128 invocations. Its F32 name describes the RHS input: exact build SPIR-V shows F16 operand staging and F32 scalar FMA sums, with no selected dot2 or F16-accumulator variant. The row path is a separate F32 shader family.

The tile converts the RHS activations too, not only the weights. In the pinned source, `mul_mm_funcs.glsl:646` casts the F32 load to `FLOAT_TYPEV8` before storing into `buf_b`; `vulkan-shaders-gen.cpp:505` and the following vector cases choose half types for this build. The selected SPIR-V hash still matches the recorded `fdd3f0ba...a146f` artifact, whose conversions and F32 FMAs confirm that path. At the time of this Radeon witness (2026-10-25), llmx's NVFP4 `matrix_input` left F32 inputs unchanged except in the separate BF16 build. The later private native-F16 staging checkpoint is described in [STATUS](../STATUS.md).

The [native half weight screen](nvfp4-native-half-weight-screen-20261025.json) retained F32 activations and sums. It did not test this RHS conversion, so its near-flat timings do not settle the value of F16 activation storage. This identifies an arithmetic and storage difference, not its contribution to the speed gap. An F16-input experiment needs matching path reporting and independent reference controls; it must preserve explicit F32 behavior and does not inherit the frozen F32-fallback reference map unchanged.

MX applies global weight scale after the dot (`src/llama-graph.cpp:1735`; expert paths 2021/2045/2173). This observation changes neither llmx's effective-weight-before-product ownership nor its precision policy. Initial nested MSBuild path failure and parent Git identity leakage are retained; a short build path and Git ceiling fixed the diagnostic build. The debug log is not timing evidence. This Radeon capture did not witness MI50. A later MI50 P128 debug dispatch and source trace are recorded in [the MI50 MX arithmetic trace](nvfp4-mx-arithmetic-trace-20261026.json). That evidence covers the P128 dispatch/library and scalar shader path. It does not include a P4096 debug capture or a successful post-run context assertion. [Exact pins, source anchors and raw-log hash](nvfp4-mx-dispatch-witness-20261025.json).

A separate prospective storage proof calls the independent spec decoder for all 4096 raw encodings/262144 values: binary16 storage and F32 widening preserve decoded bits, including signed zeros. Raw maximum is 2880; finite scale bytes 0..126 peak at 2688, with minimum nonzero 2^-10. Source and output pins are retained in the JSON. This proves storage only, not GPU execution or speed; any next scratch screen keeps global scale before the dot and F32 activations/sums.
