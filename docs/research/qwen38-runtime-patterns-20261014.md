## Stage recommendation

1. Finish the tiny HF reference/fixtures, then CPU/Vulkan math with resident test weights.
   State is concrete: GDN+PLE conv/token tail; QSA KV+raw index keys.
2. Preserve requested dtype and explicit F32 boundaries; use pinned HF output, not another engine, as numeric oracle.
3. Avoid a duplicate full token transcript if pass IDs plus the last `ngram_size-1` IDs suffice.
   Persist that integer tail transactionally through commit, rollback, fork/retract and disk restore; verify pass input history before relying on it.
4. Keep the huge table immutable.
   Later table I/O requires storage-before-allocation, bounded gathers, owned ID/staging buffers and ticketed lifetime.
   Keep it outside history eviction; start with a small host-backed fixture after Vulkan and measure before selecting I/O policy.

No external performance claims are used here.
Strata and vLLM source demonstrate mechanisms and failure modes; their measurements do not transfer to llmx hardware, dtype, backend or workload.
