# `src/backends/device_profile.hpp` - what a GPU backend shapes its kernels by

Device numbers in namespace `backend`, apart from any one vendor's API. The
Vulkan and ROCm backends fill and read them today; another GPU backend can
share them (`docs/ROADMAP.md` 4b). Branch on what a device reports, never on its
vendor name.

- `pci_root_of(domain, bus, device, function)`: the PCI root complex above a device at that address as Linux's sysfs names it (pci0000:80), or empty where the system does not say; the Vulkan and ROCm backends both report it.
- `DeviceCaps`: what the device reports, filled by the backend from its own
  API: subgroup width, compute units, the names the device and its driver
  give themselves, whether it has an integer dot product, and the shared memory a workgroup may hold (`shared_bytes`). A capability
  decides which kernel to launch.
- `DeviceProfile`: numbers found by measuring the kernels, which nothing in `DeviceCaps` implies: the lanes a Q4_K or Q5_K row takes at most in the integer-dot row kernels, the columns the widest build of the Q8_0 decode kernel holds and the forms its builds may take, among them the half-block order, which changes the device's decode results where it is set and which every build then takes, the row width below which its one-column chunk takes the build of two rows and one step, and for 8-bit and for 16-bit activations the output rows of a call from which a wider one leaves the build of one row and four steps, the columns the widest two-row decode build of the Q4 and K-quant rows holds and whether those builds take the transposed reduction, each set only where those builds' columns were checked against the one-column build, the batch rows and prompt extents from which a matmul, a routed projection or attention takes a tile kernel, the tile split and fill targets, the row width from which the integer-dot tile may take its tallest height and the entries an expert up to which its routed calls take the narrow build, each over 16-bit and over 8-bit activations, attention's history split sizes, the tiled kernel's parts among them, the history from which a view's decode rows take a KV head's query heads a workgroup (`attention_group_from`), the complete groups from which the indexer's selection takes its wide form, dispatches per submission, and whether the matmuls take the integer dot.
  A profile number shapes the same kernel.
  A number a shader's layout fixes, such as the lanes that share a quant block or the query rows of an attention tile, is a constant beside the kernels instead, since another value would break the kernel rather than tune it.
- `TunedDevice`, `tuned_devices()`: the devices and drivers the profile was tuned on, keyed by a substring of each name, each row with a function that assigns the numbers measured there by name.
  It is the table to extend when bringing up hardware, with the sweeps in `docs/VULKAN.md`.
- `profile_for(caps)`: the defaults, tuned by the first row whose device and driver both match; a row that prefers the integer dot applies only where the device has it.
- `prompt_rows_below`: read by the GPU core alone (ROCm, CUDA), the prompt extent below which a dense product runs on the decode row builds rather than the tile; the default 2 puts every prompt on the tile, and the MI50 HIP row's 9 is where the row builds stop winning for every weight type (docs/STATUS.md, ROCm prompt crossover).
- `exact_cols_upto`: read by the GPU core alone, the rows up to which an F32, F16 or BF16 exact product takes the column builds rather than the 8-by-8 row block, both giving every output its one-row bits; the default 4 is the MI50's crossover, where the 8-row column build lost to the row block at every count and shape measured, and the `sm_86` CUDA row sets `SIZE_MAX`, every count, prompts among them, since on an RTX 3090 the column builds beat the row block at every count from 2 to 512 rows for BF16 and F16 (docs/STATUS.md).
- `tile_from_for`, `tile_rows_for`: the batch rows from which a matmul of the selected family and width takes the tile, and a tile's height from the call's shape and the device's compute units.
- `rows_a_cluster(caps, rows, lanes, cap, waves_per_cu)`: the rows a cluster of `lanes` lanes takes in a decode row call of `rows` output rows, the most of 4, 2 and 1 up to the kernel's `cap` whose clusters give each compute unit `waves_per_cu` subgroups, counted as rows / r, then times lanes over the subgroup.
  ROCm's `row_build` asks it at a whole subgroup and a cap of 4 with `row_four_waves_per_cu`, the Vulkan one-column builds at their cluster with that number times their kernel's class (docs/VULKAN.md, Kernels); it knows no kernel.
- `tile_fills_twice`: whether a shared-memory tile kernel takes a call over a kernel a row, DeepSeek-V4.1's `indexer_scores` on ROCm and Vulkan. A tile block costs about a wave of the device however few of its rows are filled, so the tile takes a call when its work counted in full tiles, rows times position tiles over the tile's rows, reaches twice the blocks the device holds at once, its compute units times the tiles its shared memory holds, and never takes a tile larger than a workgroup's shared memory. On one MI50 over 362 calls of 4 to 512 rows at 256 to 16384 positions, masked and at ratio 2, the rule costs 0.66% (ROCm) and 1.18% (Vulkan) of the summed time of the faster kernel at each call, against 2.28% and 6.15% for taking the tile at every call of 4 rows a view; at a factor of 1.5 rather than 2 it costs 0.26% and 1.49% (docs/STATUS.md).
  Storage-type selection belongs to the Vulkan weight descriptor; it also selects which routed crossover field of `DeviceProfile` applies. The profile holds the measured numbers without a second storage-type dispatch.
- `split_parts`, `split_blocks`, `split_partials_most`: the one rule by which a tile call splits its inner dimension, which both GPU backends' tiles follow: a call of fewer workgroups than the profile's target a compute unit splits into the parts that fill it, each summing at least `tile_split_min_blocks` blocks, `split_blocks` the blocks a part sums at an even count; `split_partials_most` prices the most partials a call over a pass's rows keeps by the same `split_parts`, at the widest of the targets.
- `sparse_few_heads`, `sparse_few_two`: the heads a block of the few-row sparse attention pair takes from the call's rows, heads and compute units, and whether its values kernel takes two columns a lane (docs/src/backends-gpu.md); the GPU core picks the builds by them and the backends' tests name the builds they expect.

A number a shader's layout fixes, such as the lanes that share a quant block, is a constant beside the kernels and not a profile number, since another value would break the kernel rather than tune it.

Bringing up a device: fill `DeviceCaps`, check whether a capability calls for a kernel that does not exist yet, measure, and give `tuned_devices` a row that assigns the numbers measured there.
