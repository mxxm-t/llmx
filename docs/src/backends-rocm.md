# `src/backends/rocm/` - the ROCm backend

The ROCm backend over HIP ([ROCM](../ROCM.md)), built only with `LLMX_HAS_BACKEND_ROCM` on Linux, in progress as step 2 of that plan: dense F32 models on one device.

- `rocm_runtime.hpp`: the HIP runtime opened at run time with `dlopen`, its calls in one table (`hip()`) loaded by their exported names, so a build with the backend still runs where no ROCm is installed; a test substitutes a call in it to inject a failure. A missing library, call or device throws `RocmUnavailable`, which the caller reports as a missing device. `hip_check` turns a failed call into a runtime error naming the call and the runtime's reason.
- `rocm_device.hpp`: a device as HIP reports it (`rocm_device(index)`): its wave width, compute units, name and runtime version in `DeviceCaps` ([device_profile](backends-device_profile.md)), and beside them its ISA, memory, PCI address and root complex (`pci_root_of`).
- `rocm_backend.hpp`: `make_rocm_backend(index)`, the one entry the device factory ([devices](backends-devices.md)) reaches for `--device rocm:N`.
- `rocm_backend.cpp`: the backend, a translation unit of its own as the Vulkan backend's is.
  - Execution: one non-blocking HIP stream a device, every op an asynchronous launch on it; `submit()` records an event from a ring of 1024 and returns its ticket from the shared `TicketLedger` ([backend](backends-backend.md)), and a slot is reused only once its earlier ticket has retired. `wait` synchronises on the ticket's event and `done` queries it.
  - Memory: `alloc` is device memory zero-filled on the stream, or pinned host memory the device reads in place (`Memory::host_visible`); `write` and `read` go through a pinned staging ring, and host values a kernel reads (positions, ids, block tables) through an argument ring, each slot reused once the ticket that last read it retires.
  - Errors: a call refused as it is enqueued throws at once; a failure the device reports at an event is kept as the first cause, which `raise(t)` before results are read in place, `read` and the next launch or submission throw.
  - KV: blocks of 64 tokens through the shared `BlockKVStorage`, F32 or F16 sides, an old buffer a growth copied from held until the copies retire.
  - Ops: `matmul`, `matmul_add` (and through them `matmul_group` and `matmul_logits`) on F32 and Q8_0 weights, Q8_0 decoded exactly into F32 sums, `embed` of an F32 or Q8_0 table, `gather_rows`, `rms_norm_rows`, `norm_rope_partial` with one rope stream, `silu_mul`, `add`, `copy`, `kv_write` and `attention`. Every other weight type and named op is refused at load (`supports_type`, `implements`), and `join` keeps the default, so tensor groups are refused until step 4.
  - Batch invariance: every kernel computes a row from that row alone in a fixed order, so `row_class` makes a generated token one class and every prompt row another.
- `kernels/f32.hip`: the dense F32 kernels, compiled at build time to a code object for gfx906 and gfx1151 (compile coverage only) and embedded as a byte array (`cmake/embed.cmake`), as the Vulkan SPIR-V is. Every sum is F32, folded by one block tree whatever the wave width; attention is an online softmax in position order.

`rocm-runtime` (CTest) opens device 0, checks the facts it reports, round-trips 4 MiB from pinned host memory to the device and back on one stream with an event, and checks that an allocation past the device's memory is refused by name. `backend-rocm` checks the backend's buffers, tickets and refusals and holds each op to the CPU backend and to its own rows alone. Both exit 77 without a runtime or a device.
