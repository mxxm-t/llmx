# `src/backends/rocm/` - the ROCm backend

The ROCm backend over HIP ([ROCM](../ROCM.md)), built only with `LLMX_HAS_BACKEND_ROCM` on Linux: the shared GPU core and kernels ([backends-gpu](backends-gpu.md)) over the HIP runtime, its kernels compiled for each target and embedded.

- `rocm_runtime.hpp`: the HIP runtime opened at run time with `dlopen`, its calls in one table (`hip()`) loaded by their exported names, so a build with the backend still runs where no ROCm is installed; a test substitutes a call in it to inject a failure. A missing library, call or device throws `RocmUnavailable`, which the caller reports as a missing device. `hip_check` turns a failed call into a runtime error naming the call and the runtime's reason.
- `rocm_device.hpp`: a device as HIP reports it (`rocm_device(index)`): its wave width, compute units, name, runtime version and a workgroup's shared memory in `DeviceCaps` ([device_profile](backends-device_profile.md)), and beside them its ISA, memory, PCI address and root complex (`pci_root_of`), and its `DeviceProfile`, which the backend takes once from `profile_for` after it knows the integer dot and reads wherever a kernel's shape follows the profile.
- `rocm_backend.hpp`: `make_rocm_backend(index)`, the one entry the device factory ([devices](backends-devices.md)) reaches for `--device rocm:N`.
- `rocm_backend.cpp`: the backend, a translation unit of its own as the Vulkan backend's is: the embedded code objects of `gpu/kernels` (`f32`, `int16`, and `int16dot` for the targets with the 16-bit integer dot), `HipApi`, the core's calls over the runtime table, each through `hip()` at the call so a test's substitute reaches the backend, and the core instantiated over it, with the entries `rocm_backend.hpp` declares (`rocm_take_launches`, `rocm_route_only`, `rocm_profile`, `rocm_collective`).

The Flash-Next stream and conv ops and the auxiliary planes are held by the device-agnostic `stream-ops`, `dilated-conv` and `kv-auxiliary` with `--device rocm:N`, and the per-layer embedding and hyper-connection helpers by `llmx-qwen4exp-graph-test --device rocm:N` (docs/TESTS.md). `rocm-runtime` (CTest) opens device 0, checks the facts it reports, round-trips 4 MiB from pinned host memory to the device and back on one stream with an event, and checks that an allocation past the device's memory is refused by name. `backend-rocm` checks the backend's buffers, a 256 MiB buffer dropped with 64 copies out of it queued among them, tickets and refusals and holds each op to the CPU backend and to its own rows alone; 9000 decode steps of two layers, whose pass values go round the device ring and the second layer finds the first's, give at the last step the bits of a fresh backend. Where two or more devices open, `backend-rocm` also holds the collective to the oracle `tests/group_sums.hpp` shares with `backend-vulkan`, fast, conservative, after a sum that gave up and across the epochs' wrap (docs/TESTS.md).
