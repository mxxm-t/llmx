# `src/inference/spec.hpp` - speculative decoding's acceptance, proposers and draft length

What speculative decoding adds above the model (docs/SPECULATIVE.md, section 3): the acceptance of a verify's rows, the proposers that draft, and the length of a draft. `generate` runs the round over them ([generate](inference-generate.md)); the model runtime owns the verify's history (`Model::mark`, `Model::retract`, [runtime](model-runtime.md)). Namespace `infer` for `accept`, `infer::spec` for the rest.

- `accept(rows, n_vocab, drafts, k, s, end, gen, rng, pick) -> Accepted`: the rows of a verify of `k` drafts, row i the logits after the last pick and the first i drafts, sampled in order with `infer::sample` exactly as the run without drafts samples, one call a row; `pick` takes each token as that run does and says whether the request goes on. It stops at the first pick that ends the request or differs from its draft, or after row `k`, and returns the rows sampled and the last pick, so the tokens, the draws and the end are those of the run without drafts whatever was drafted.
- `spec::Proposer`: `draft(history, k, out)`, up to `k` tokens likely to follow `history`, fewer or none where it has nothing; it drafts deterministically and never touches a request's generator, so a wrong draft costs time and never output.
- `spec::Lookup`: prompt lookup, the tokens that followed the latest earlier occurrence of the history's last three tokens, else two, else one.
- `spec::Acceptance`: a request's one acceptance figure, the average of the drafts its verifies kept, each verify moving it an eighth of the way to what it kept, starting at 2; below half a draft a verify the request drafts nothing for its next 16 tokens, then verifies once more.
- `spec::draft_length(draft_max, tokens_left, context_left, acceptance)`: the drafts a request verifies next, the one rule for every caller: at most `draft_max`, one fewer than the tokens it may still generate and than the positions its context has left, since the verify feeds the last pick and every draft, and none while it rests. It prices no draft yet: the pass cost model that would comes with the server (SPECULATIVE, step 5).
- `spec::kMaxDrafts` (63): the most drafts a verify takes, 64 rows with the last pick, the most generated tokens a pass's kernels are held to give the bits of single steps for (`backend-vulkan`).
- `spec::Drafting`: a request's proposer, its most drafts, the tokens its history held before it generated and its acceptance, which `generate` takes.
