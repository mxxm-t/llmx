# `src/model/layer_split.hpp` - a model split by layers over devices

Which consecutive layers each device runs, fitted to what each device reports free (`docs/MULTI-DEVICE.md`, phase 1). The file knows no architecture: an architecture describes what it asks of memory as a `Footprint`, and the split works on those numbers alone.

- `Footprint`: the bytes of each layer's weights, the embedding table and the head, whether the head reads the embedding table (`tied`), one layer's cache for every position the budget allows, the tables every device that runs layers holds (RoPE), and one row of a pass's activations. `infer::footprint` in `arch_qwen.hpp` computes it for Qwen3.
- `DeviceBudget`: a device's name, the bytes it reports free (`Backend::memory_available`; 0 is a device that cannot tell and is not checked), and whether its weights read the mapped file in place, as the CPU's do, rather than being copied into its memory.
- `split_layers(footprint, devices, rows, shares)`: consecutive layers per device in the order given. Devices that copy weights share the layers as evenly as their budgets allow, filled level by level; host devices take only what the others cannot hold. The embedding goes with the first device that runs layers and the head with the last, so the fit repeats until the set of devices running layers stops changing. `shares`, when given, is each device's proportion of the layers, rounded by largest remainder so the counts add up; the fit is still checked. A device must hold its layers' weights where it copies them and their caches, the embedding and head where they sit (once when tied and on one device), the tables, `rows` rows of activations, and where it copies weights a reserve of 256 MiB plus a twentieth of its budget for tile split partials, attention merge state and padded F32 copies. A model that does not fit throws with the number of layers left without room.
- `LayerSplit`: per device its first layer, layer count and the weights, cache and other bytes it was fitted to hold, plus the embedding and output devices; `describe` renders it for `--verbose`. `placement_for` in `arch_qwen.hpp` turns it into the model's `Placement`.

`tests/placement.cpp` checks even shares, a device without room left out, a host device given nothing another device can hold, devices of unknown room, shares as proportions and their refusals, and that a model built from the fitted placement over two CPU backends gives the bytes of one.
