# `src/model/layer_split.hpp` - a model split by layers over devices

Which consecutive layers each device runs, fitted to what each device reports free (`docs/MULTI-DEVICE.md`, phase 1). The file knows no architecture: an architecture describes what it asks of memory as a `Footprint`, and the split works on those numbers alone.

- `Matrix`: one weight as a device would adopt it: quant type, row width, row count, bytes in the file, and `product`, whether a matrix product reads it as its weights (projections and the head) rather than a gather, a norm or a routed expert stack.
- `Footprint`: each layer's matrices, the embedding table, the head's matrix (the embedding itself when `tied`) and its norm, one layer's cache for every position the budget allows, the position tables (RoPE), which the host keeps while the model lives and every device that copies weights holds again, one row of a pass's activations, one row of logits, and one row of the stream handed between devices through host memory. `infer::footprint` in `arch_qwen.hpp` computes it for Qwen3.
- `DeviceBudget`: a device's name; the bytes it reports free (`Backend::memory_available`), absent when it cannot tell, which is not checked, while a reading of zero is a full device; whether its weights read the mapped file in place, as the CPU's do; and `resident`, what adopting a matrix keeps on it (`Backend::resident_bytes`: the Vulkan backend adds the padded copy it makes of an F32 product matrix whose rows are a multiple of 256 floats); and `host_side`, host memory its backend holds for itself such as upload staging (`Backend::host_resident`).
- `budgets_for(backends, names)`: each backend's budget, asked of the backend: `memory_available()`, `reads_in_place()`, `resident_bytes`, `host_resident()` and `scratch_reserve()`, the memory its kernels keep for themselves (`DeviceBudget::scratch`).
- `split_layers(footprint, devices, rows, shares, host_free)`: consecutive layers per device in the order given. For every set of devices that could run layers, each running at least one, the first carrying the embedding and the last the head, a small dynamic program assigns the layers by their actual sizes, every device within its budget, with the fewest layers on host devices and then the lightest busiest device; the best of those sets by the same order is kept (a machine's devices are few, at most 16 are taken), so a host device takes a layer back when moving the embedding leaves a device short, and three equal devices share three equal layers one each. `shares`, when given, is each device's proportion of the layers, rounded by largest remainder; the fit is still checked. A device must hold its layers' weights as it keeps them resident and their caches, the embedding and the head where they sit (a tied pair once on one device, the head's norm always), `rows` rows of activations (the CLI passes a prompt's ubatch plus a server's sequences), and where it copies weights its own tables and its kernels' scratch (`DeviceBudget::scratch`: the Vulkan backend keeps 256 MiB plus a twentieth of what is free for tile split partials and attention merge state). The host holds, for the set a plan uses, `rows` rows of logits (host-visible memory it reads in place), the position tables, two handoff buffers of `rows` rows per device when more than one device runs layers, and the `host_side` of each device in the set, never of a device left out, so a device whose staging the host cannot hold is left out when the others can run the model. The set's first host device carries that, since its budget is the host's memory, and its tables are that same memory, counted once; without one it must fit the first host device listed or, with none listed, `host_free`, the host's available memory, which is not checked when absent. The logits rows are a bound: a pass's rows all return logits when a text is scored, while generation returns fewer. A model that does not fit throws. `LayerSplit::host` is that amount, printed with the stages.
- `LayerSplit`: per device its first layer, layer count and the weights, cache and other bytes it was fitted to hold, plus the embedding and output devices; `describe` renders it for `--verbose`. `placement_for` in `arch_qwen.hpp` turns it into the model's `Placement`.

`tests/placement.cpp` checks even shares, a device without room left out, a host device given nothing another device can hold and taking a layer back when endpoint weights leave the device short, layers of unequal size placed by their sizes, three equal devices one layer each, tied weights counted once with the norm, a backend's resident copies counted, unknown and zero budgets kept apart, shares as proportions and their refusals, the host's logits counted on the host device or against its free memory, its tables, handoff and staging counted for the devices a plan uses (one device chosen when the host cannot stage two, shares leaving a device out not charging it) and the tables once when a CPU carries them, that a model built from the fitted placement over two CPU backends gives the bytes of one, and through `infer::place_model` that budgets are asked of the backends, a split by shares gives the bytes of one device, the request's ubatch is applied, and experts on the CPU are refused beside several devices.
