# `src/quant/model_formats.hpp` - DeepSeek-V4.1's own storage formats

`quant::model_formats` packs a block into its bytes and reads them back, as DeepSeek-V4.1's kernels store its caches (docs/DEEPSEEK4.md, section 4.5), and quantizes and dequantizes a block in place in F32 as the packed block's values: `qdq_fp8_power`, the window's FP8 E4M3 under a power-of-two scale, `qdq_fp4_power`, the index keys' and queries' FP4 E2M1 under a power-of-two scale, and `qdq_fp4_e4m3`, the entries' FP4 E2M1 under an E4M3 scale.
A power-of-two scale is `power_scale`: `ceil_log2`'s bit rule (the exponent field less 127, plus one where any mantissa bit is set) of the block's floored largest magnitude times the format's inverse maximum, one F32 multiply, then `pow2`; the floors are 1e-4 for FP8 and 6 x 2^-126 for FP4.
The E4M3 scale is the code nearest amax / 6, amax floored at 6 x 2^-9 so it is never zero, saturating at 448 as the kernels' conversion does.
`e4m3_code` and `e2m1_code` choose codes by exact comparisons, ties to even, each zero keeping its sign; `e4m3_value` and `e2m1_value` decode them, and a stored value is one F32 multiply of a code's value and the scale, so every backend writes the same bytes for the same inputs.
The packed blocks are the cache type `native`'s (docs/DEEPSEEK4.md, section 4.3), each a scale byte then the codes: `pack_fp8_power` 33 bytes, an E8M0 byte then 32 E4M3 codes; `pack_fp4_power` 17 bytes in the GGUF MXFP4 block, an E8M0 byte then 16 bytes whose low nibbles are values 0 to 15 and high nibbles 16 to 31; `pack_fp4_e4m3` 9 bytes, an E4M3 byte then 8 bytes laid out the same way.
`unpack_*` reads value i of a block as code times scale, `e8m0_value` building the scale from its exponent field, and each `qdq_*` is its format's pack then unpack, so the F32 a cache of type f32 holds and the bytes of one of type native read back alike.
CTest `deepseek4-ops` holds these functions to E4M3 and E2M1 written from their text and the key block to the MXFP4 weight decoder.
