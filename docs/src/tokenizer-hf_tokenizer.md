# `src/tokenizer/hf_tokenizer.hpp` - Hugging Face tokenizer files to the GGUF tokenizer keys

`bpe::hf::read_keys(dir, config, n_vocab)` reads a Hugging Face directory's `tokenizer.json`, `tokenizer_config.json` and, when present, `chat_template.jinja`, and returns the `tokenizer.*` keys the GGUF converter writes for the same checkpoint, so `bpe::Tokenizer` ([tokenizer](tokenizer-tokenizer.md)) and the chat template read a directory as they read its GGUF file.
`config` is the object of the directory's `config.json` that holds the text model's keys (`hf::keys_of`, [hf_config](model-arch-hf_config.md)) and `n_vocab` the embedding's rows.

What it writes:
- `tokenizer.ggml.model` `gpt2` and `tokenizer.ggml.pre` `qwen2`, or `qwen35` for the Split pattern of Qwen 3.5 and 3.6 files, which adds combining marks to the letter runs; any other pattern is refused.
- `tokenizer.ggml.tokens` and `tokenizer.ggml.token_type` (INT32), `n_vocab` long: the model's vocabulary as normal tokens (1), added tokens as control (3) when `special` or written `<|name|>`, else user-defined (4), and every id neither uses as `[PAD<id>]`, unused (5).
- the added tokens `tokenizer_config.json`'s `added_tokens_decoder` gives at ids `tokenizer.json` does not list, as Qwen 3.5's seven audio and speech tokens (248070 to 248076), taken as `tokenizer.json`'s added tokens are, since HF's tokenizer and the converter take them; a `pretokenize_regex` there must be the Split pattern.
- `tokenizer.ggml.merges`, each `"a b"`, from either form a file uses (`"a b"` or `["a", "b"]`).
- `bos`, `eos`, `unknown` and `padding` token ids: the added token whose text `tokenizer_config.json` names, else the id `config.json` gives below `n_vocab`; a pad text that names no token, as gptqmodel writes `<unk>`, gives no id from the text, as HF's tokenizer gives none.
- `tokenizer.ggml.add_bos_token` and `add_eos_token` when `tokenizer_config.json` sets them.
- `tokenizer.chat_template`: `chat_template.jinja` when present, else `tokenizer_config.json`'s `chat_template`.

What it refuses, each by name: a key of either file it does not list; a normalizer other than NFC, which the tokenizer applies for `qwen2` and `qwen35`; a pre-tokenizer other than the qwen2 or qwen35 Split (`Isolated`, not inverted, the pattern byte for byte) followed by ByteLevel; a ByteLevel step, post-processor or decoder that adds a prefix space or uses its own regex; a post-processor other than ByteLevel or null; a model other than plain byte-level BPE (dropout, unknown token, prefixes, suffixes, byte fallback, ignored merges); a token id at or past `n_vocab` or given twice; an added token that takes another token's id, strips, matches single words or is normalized; a merge not of two non-empty parts without spaces; `add_bos_token`, `add_eos_token`, `add_prefix_space`, `clean_up_tokenization_spaces` or `split_special_tokens` set, which the tokenizer does not implement; a bos, eos or unknown token text that is not an added token; an `extra_special_tokens` that is not a map or a list, or a text in it that is not an added token; a list of named chat templates; an `added_tokens_decoder` entry that differs from `tokenizer.json`'s token.
tokenizer.json `truncation` and `padding` are taken whatever they hold: llm-compressor saves those of its calibration, and transformers 4.55.2 clears both on every encode it is not asked to cut or pad, so they change no id.
tokenizer_config.json's `max_length`, `stride`, `truncation_side`, `truncation_strategy` and `padding_side`, where transformers 4.55.2 saves the same settings, are taken the same way: it keeps them as init kwargs that no encode reads unless asked to cut or pad (a 60000-byte text gives the same 14911 ids through AutoTokenizer with `max_length` 2048 as through the untruncated tokenizer).

The converter also makes control tokens of a few other forms, such as a name between `<` U+FF5C and U+FF5C `>` (fullwidth bars); this reader does not, so a file whose specials take such a form, none of the qwen2 files, would give type 4 where its GGUF file gives 3.

On Qwen/Qwen3-0.6B at c1899de the keys equal those of `Qwen/Qwen3-0.6B-GGUF`'s Q8_0 file but its older chat template, and the directory's tokenizer gives HF's ids on the 20 texts of `tests/data/baseline_tokenizer.json`.
`unsloth/Qwen3-0.6B-BF16.gguf` also differs in having no BOS id and a padding id of 151654, edits of that file.
